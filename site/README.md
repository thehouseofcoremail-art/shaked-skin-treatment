# המרווח · THE MARGIN

מגזין מנויים על **הצד העסקי** של תעשיית הכושר בישראל — תמחור, תזרים, נטישה, גיוס ושכר מדריכים.
מרווח הוא גם שולי הרווח וגם מרחק — והשורה התחתונה של המגזין היא בדיוק מה שנשאר בסוף החודש.
מודל ההכנסה זהה לזה שראית ב-Business Insider: קצת חינם, מונה קריאות, ואז חומת תשלום.

אתר סטטי ללא תלויות + פונקציות שרת קטנות לסליקה ולהרשאות. אין מסד נתונים, אין שרת לתחזק.

---

## בשתי פקודות

```bash
cd site
npm run build          # בונה את האתר לתוך public/
npx serve public       # או כל שרת סטטי אחר
```

הכול עובד חוץ מהסליקה וההתחברות — אלה דורשות את השלבים שלמטה.
בלי שרת מחובר האתר נכנס אוטומטית ל**מצב תצוגה מקדימה** ואומר את זה במפורש בעמוד החשבון.

## איך הגבייה עובדת

```
קוראת מגיעה לכתבה
        │
        ├── כתבה פתוחה .......................... קוראת הכול
        │
        └── כתבה למנויים
                 ├── מנוי פעיל .................. /api/article/:slug מחזיר את הגוף
                 ├── נשארו קריאות חינם ........... "שימוש בקריאה חינם" (מונה בעוגייה חתומה)
                 └── נגמרו ....................... חומה + מסלולי מנוי
```

**הגוף של כתבה בתשלום לא נמצא ב-HTML.** `build.mjs` מפצל כל כתבה בסימן `<!--paywall-->`:
פסקאות הפתיחה נכנסות לעמוד הסטטי (וגם ל-Google, שזה מה שמביא תנועה), והשאר נכתב ל-`functions/_data/bodies.js`
ומוגש רק דרך ה-API אחרי בדיקת הרשאה. אי אפשר לעקוף את זה עם "הצג מקור" או בכיבוי JavaScript.

לבדיקה בעצמך:

```bash
grep -r "אורך חיים ממוצע" public/     # לא יחזיר כלום
grep -c "אורך חיים ממוצע" functions/_data/bodies.js
```

## עלייה לאוויר — Cloudflare Pages

חינם עד רמות תעבורה גבוהות, ותומך בפונקציות שהפרויקט משתמש בהן.

**1. יצירת מקום לאחסון המנויים**

```bash
npx wrangler kv namespace create MEMBERS
```

את ה-`id` שהפקודה מחזירה מדביקים ב-`wrangler.toml`.

**2. פרסום**

```bash
npm run deploy
```

או לחבר את ה-repo ב-Cloudflare Dashboard עם ההגדרות:
תיקיית שורש `site` · פקודת בנייה `npm run build` · תיקיית פלט `public`.

**3. הסודות** (אף אחד מהם לא נכנס ל-git)

```bash
npx wrangler pages secret put SESSION_SECRET        # מחרוזת אקראית ארוכה, ממציאים פעם אחת
npx wrangler pages secret put STRIPE_SECRET_KEY
npx wrangler pages secret put STRIPE_WEBHOOK_SECRET
npx wrangler pages secret put STRIPE_PRICE_MONTHLY
npx wrangler pages secret put STRIPE_PRICE_ANNUAL
npx wrangler pages secret put STRIPE_PRICE_TEAM
npx wrangler pages secret put RESEND_API_KEY
npx wrangler pages secret put MAIL_FROM
```

## חיבור התשלומים (Stripe)

1. פותחים חשבון Stripe ומפעילים **Billing**.
2. יוצרים שלושה Products עם מחיר מתחדש בשקלים — חודשי, שנתי, סטודיו.
   כל אחד מחזיר `price_...` שנכנס לסוד המתאים למעלה.
3. מוסיפים Webhook שמצביע ל-`https://הדומיין-שלך/api/stripe-webhook` ובוחרים את שלושת האירועים:
   `checkout.session.completed` · `customer.subscription.updated` · `customer.subscription.deleted`.
   ה-`whsec_...` שמתקבל נכנס ל-`STRIPE_WEBHOOK_SECRET`.

ה-Webhook הוא מה שמבטל גישה כשמנוי נעצר. בלעדיו מנוי שביטל ימשיך לקרוא.

**מחשבה לפני שמתחילים:** Stripe עובד בישראל ותומך בשקלים, אבל **אינו מוציא חשבונית מס ישראלית**.
צריך לחבר מערכת חשבוניות (Green Invoice, iCount, Morning וכד׳) או לבחור סולק ישראלי.
להחלפת ספק סליקה נוגעים בשלושה קבצים בלבד: `functions/api/checkout.js`, `activate.js`, `stripe-webhook.js`.
שאר האתר לא יודע מי מחייב.

## חיבור המייל (Resend)

משמש לקישורי הכניסה. נרשמים ב-Resend, מאמתים דומיין, ומזינים את `RESEND_API_KEY` ואת `MAIL_FROM`.
ספק אחר — מחליפים רק את `functions/_lib/mail.js`.

## כתיבת גיליון חדש

קובץ אחד. זה כל התהליך.

```bash
cp content/articles/06-sachar-madrichot.md content/articles/07-הנושא-שלי.md
# עורכים, ואז:
npm run build
```

מבנה הקובץ:

```markdown
---
slug: shem-bagnlit          # הכתובת באתר: /a/shem-bagnlit/
title: הכותרת
dek: פסקת הפתיחה שמופיעה בעמוד הבית ובגוגל
category: מודל              # מודל · תזרים · תפעול · פתח דבר
date: 2026-09-20
issue: 2
premium: true               # false = פתוח לכולם
readingTime: 8
tags: [תמחור, תזרים]
---

הפסקאות שלפני הסימן למטה גלויות לכולם. כאן שמים את הפתיחה
שגורמת למישהי לרצות את השאר.

<!--paywall-->

מכאן והלאה — למנויים בלבד.
```

נתמכים: כותרות, רשימות, טבלאות, ציטוטים, בלוקי נוסחה, מודגש ונטוי, וארבעה קיצורים שמשתילים מחשבון בתוך הכתבה:
`{{calc-unit}}` · `{{calc-churn}}` · `{{calc-pricing}}` (ו-`{{calculator}}` כשם נרדף ליחידת הכלכלה).

**המדור קובע את העטיפה.** לכל כתבה נוצרת תמונת שער אוטומטית מה-slug שלה, בדפוס שנקבע לפי המדור —
קווי גובה, זרימה, עמודות או טבעות. אותה כתבה תיתן תמיד את אותה תמונה, ואין צורך בתמונות מלאי.
מדור חדש שלא מופיע ב-`COVER_FAMILY` שב-`build.mjs` יקבל קווי גובה כברירת מחדל.

הבנייה מדפיסה בסוף רשימת דברים שצריך לטפל בהם לפני פרסום. כדאי לקרוא אותה.

## קרוסלות לאינסטגרם

המגזין הוא המוצר, אינסטגרם היא ההפצה. כל כתבה הופכת לקרוסלה מוכנה לפרסום
בלי לפתוח קאנבה:

```bash
npm run social                          # כל הכתבות
python3 social/build_social.py netisha  # כתבה אחת
```

הפלט: `social/out/<slug>/01.png … NN.png` — 1080x1350, בדיוק אותה שפה עיצובית
של האתר, כולל הדפוס הגנרטיבי של אותה כתבה ברקע.

**מבנה הקרוסלה** נקבע מהכתבה עצמה: שקף פתיחה עם הכותרת (הפסוקית השנייה בפריוונקל),
שקף הסבר לכל מונח באנגלית, שקף לכל פסקה מהחלק הפתוח, שקף נוסחה אם יש,
שקף "מה יש בפנים", ושקף סיום עם הדומיין.

**מה לא נכנס לשקפים: אף משפט מגוף הכתבה בתשלום.** מה שכן נכנס זה כותרות המשנה
של החלק בתשלום, בשקף "מה יש בפנים" — זה תוכן עניינים, לא הניתוח, וזה שקף ההמרה
החזק ביותר. למי שמעדיפה בלעדיו: `python3 social/build_social.py --no-toc`.

### מונחים באנגלית

קיצור באנגלית בתוך טקסט עברי הוא חומה: מי שלא יודע מה הוא אומר מפסיק לקרוא
שם, לא בסוף. לכן כל מונח שמופיע בטקסט **הגלוי** של קרוסלה מקבל הסבר לפניו —
מה הקיצור אומר ולמה הוא חשוב, ואז איך מחשבים אותו ומה כל רכיב בנוסחה.

המילון יושב ב-`content/glossary.json`, קובץ אחד לעריכה:

```json
"CAC": {
  "he":  "עלות גיוס של לקוחה אחת משלמת",
  "en":  "Customer Acquisition Cost",
  "why": "שורה-שתיים: למה המספר הזה משנה לקורא.",
  "formula": "CAC = סך ההוצאה על גיוס ÷ לקוחות משלמות שנוצרו ממנה",
  "parts": [["סך ההוצאה", "מה נכלל בו ומה נשכח"],
            ["לקוחות משלמות", "מי נספרת ומי לא"]]
}
```

`formula` ו-`parts` אופציונליים — מונח בלעדיהם (GLP-1, CRM) מקבל שקף אחד.
מונח איתם מקבל שניים: הסבר, ואז "איך מחשבים" עם פירוק הרכיבים.

שלושה כללים שהמחולל אוכף לבד:

- **רק מה שנראה.** מונח שמופיע רק בחלק בתשלום לא מקבל שקף — אף אחד לא ייתקל
  בו בקרוסלה. נבדקים הכותרת, הדק, פסקאות הגוף הפתוח, כותרות ה-TOC והנוסחה.
- **שניים לכל היותר.** שלושה שקפי הסבר ברצף הופכים קרוסלה לשיעור.
- **בלי כפילות.** אם נוסחת הכתבה היא בדיוק הנוסחה של המונח, שקף הנוסחה
  הגנרי נדלג.

ההסבר נכנס מיד אחרי שקף הפתיחה ולפני אריחי המספרים, כי התוויות שלהם כבר
משתמשות במונח.

דורש `pip install Pillow` עם Raqm — בלעדיו העברית תצא מהופכת. הגופנים
(Heebo, IBM Plex Mono, ברישיון OFL) יושבים ב-`social/fonts/`.

> **שכבת המונו היא לטינית ומספרים בלבד.** ל-IBM Plex Mono אין אותיות עבריות,
> ולכן כל תווית עברית נופלת ל-Heebo אוטומטית. בדפדפן מחסנית הגופנים עושה את זה
> לבד; ב-Pillow אין נפילה כזו, וזה מה שהפונקציה `LABEL` פותרת.

## שינוי מחירים, שם ומיתוג

הכול ב-**`site.config.json`** — שם המגזין, שם הכותבת, הביו, המחירים, מספר הקריאות החינם והדומיין.
משנים, מריצים `npm run build`, וזה מתגלגל לכל העמודים.
`0` בשדה `freeArticlesPerMonth` מבטל את המונה ויוצר חומה קשיחה.

השאלות הנפוצות נמצאות ב-`content/faq.json`, ועמודי המידע ב-`content/pages/`.

## לפני שזה עולה לאוויר

הרשימה הזו אמיתית. שלושת הראשונים חוסמים.

- [ ] **התוכן.** אחת-עשרה הכתבות הן **טיוטות זרע שנכתבו כדי להראות את המבנה** — מסגרות חשיבה נכונות, אבל לא הדיווח שלך. אין בהן נתוני שוק ישראליים אמיתיים, וזה במכוון: המצאת "ממוצע שוק" הייתה הופכת את המוצר לחסר ערך. להחליף בכתיבה שלך לפני שגובים כסף.
- [ ] **עמודי תנאי השימוש והפרטיות** הם טיוטות שמרניות, לא מסמכים משפטיים. **חייבים בדיקת עורך דין** — במיוחד סעיפי הביטול, שכפופים לחוק הגנת הצרכן.
- [ ] **חשבונית מס.** לסגור את זה מול רואה החשבון לפני החיוב הראשון, לא אחריו.
- [ ] שם הכותבת, הביו וכתובת המייל ב-`site.config.json` (כרגע `רומי` ו-`hello@example.co.il`).
- [ ] המחירים — ₪45 לארבעה שבועות, ₪390 לשנה, ₪1,490 לצוות — הם **נקודת פתיחה סבירה, לא מחקר שוק**.
- [ ] ברירות המחדל של שלושת המחשבונים הן מספרי המחשה. הן מופיעות לכל מבקר, אז כדאי שיהיו סבירות לשוק שלכם.
- [ ] הדומיין ב-`site.config.json` (משפיע על ה-canonical, ה-sitemap וה-RSS).
- [ ] `SESSION_SECRET` — מחרוזת אקראית ארוכה. החלפה שלה מנתקת את כל המנויות.
- [ ] לבדוק רכישה מקצה לקצה עם כרטיס הבדיקה של Stripe, **וגם** ביטול, ולוודא שהגישה נחסמת.

## מבנה

```
site/
├── site.config.json        מותג, כותבת, מחירים     ← נקודת העריכה הראשית
├── build.mjs               הגנרטור. ללא תלויות
├── content/
│   ├── articles/*.md       הגיליונות
│   ├── pages/*.md          על הטור, תנאים, פרטיות
│   └── faq.json            שאלות נפוצות
├── public/                 הפלט. נבנה מחדש, לא לערוך ידנית
│   ├── covers/             עטיפות SVG שנוצרות אוטומטית לכל כתבה
│   └── assets/             site.css · site.js   ← אלה כן נערכים ידנית
├── social/
│   ├── build_social.py     מחולל הקרוסלות לאינסטגרם
│   ├── fonts/              Heebo + IBM Plex Mono (OFL)
│   └── out/<slug>/NN.png   הפלט, מוכן להעלאה
├── functions/
│   ├── _data/bodies.js     גופי הכתבות בתשלום. נוצר אוטומטית
│   ├── _lib/               חתימות, Stripe, מייל
│   └── api/                session · article · checkout · activate · login · magic · portal · webhook
└── test/
    ├── auth.test.mjs       חתימות, מונה קריאות, אימות webhook
    ├── paywall.test.mjs    שאף משפט בתשלום לא דלף ל-public/
    └── ui.test.mjs         npm run test:ui
```

**עמודי האתר:** בית · ארכיון (לפי מדורים) · כתבה · שלושה עמודי מחשבון · ריכוז המחשבונים ·
מנוי · חשבון · על המרווח · תנאים · פרטיות · 404 · RSS · sitemap.

`npm test` בודק את החתימות, את מונה הקריאות ואת אימות ה-Webhook — כולל ניסיונות זיוף —
ואז לוקח כל משפט מכל כתבה בתשלום ומוודא שהוא לא מופיע באף קובץ שמוגש לדפדפן.
`npm run test:ui` מריץ דפדפן ובודק שחומת התשלום סגורה, שהמחשבונים מחשבים, שהעטיפות מוגשות
ושכל הקישורים בעמוד הבית עובדים. דורש playwright. כדאי להריץ את שניהם לפני כל פרסום.
