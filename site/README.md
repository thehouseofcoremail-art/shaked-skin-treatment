# מאחורי המראות

מגזין מנויים על **הצד העסקי** של תעשיית הכושר בישראל — תמחור, תזרים, נטישה ושכר מדריכים.
מודל ההכנסה זהה לזה שראית ב-Business Insider: קצת חינם, מונה קריאות, ואז חומת תשלום.

אתר סטטי ללא תלויות + פונקציות שרת קטנות לסליקה ולהרשאות. אין מסד נתונים, אין שרת לתחזק.

---

## בשתי פקודות

```bash
cd site
npm run build          # בונה את האתר לתוך public/
npx serve public       # או כל שרת סטטי אחר
```

הכול עובד חוץ מהסליקה וההתחברות — אלה דורשות את השלבים שלמטה.
בלי שרת מחובר האתר נכנס אוטומטית ל**מצב תצוגה מקדימה** ואומר את זה במפורש בעמוד החשבון.

## איך הגבייה עובדת

```
קוראת מגיעה לכתבה
        │
        ├── כתבה פתוחה .......................... קוראת הכול
        │
        └── כתבה למנויות
                 ├── מנויה פעילה ................. /api/article/:slug מחזיר את הגוף
                 ├── נשארו קריאות חינם ........... "שימוש בקריאה חינם" (מונה בעוגייה חתומה)
                 └── נגמרו ....................... חומה + מסלולי מנוי
```

**הגוף של כתבה בתשלום לא נמצא ב-HTML.** `build.mjs` מפצל כל כתבה בסימן `<!--paywall-->`:
פסקאות הפתיחה נכנסות לעמוד הסטטי (וגם ל-Google, שזה מה שמביא תנועה), והשאר נכתב ל-`functions/_data/bodies.js`
ומוגש רק דרך ה-API אחרי בדיקת הרשאה. אי אפשר לעקוף את זה עם "הצג מקור" או בכיבוי JavaScript.

לבדיקה בעצמך:

```bash
grep -r "אורך חיים ממוצע" public/     # לא יחזיר כלום
grep -c "אורך חיים ממוצע" functions/_data/bodies.js
```

## עלייה לאוויר — Cloudflare Pages

חינם עד רמות תעבורה גבוהות, ותומך בפונקציות שהפרויקט משתמש בהן.

**1. יצירת מקום לאחסון המנויים**

```bash
npx wrangler kv namespace create MEMBERS
```

את ה-`id` שהפקודה מחזירה מדביקים ב-`wrangler.toml`.

**2. פרסום**

```bash
npm run deploy
```

או לחבר את ה-repo ב-Cloudflare Dashboard עם ההגדרות:
תיקיית שורש `site` · פקודת בנייה `npm run build` · תיקיית פלט `public`.

**3. הסודות** (אף אחד מהם לא נכנס ל-git)

```bash
npx wrangler pages secret put SESSION_SECRET        # מחרוזת אקראית ארוכה, ממציאים פעם אחת
npx wrangler pages secret put STRIPE_SECRET_KEY
npx wrangler pages secret put STRIPE_WEBHOOK_SECRET
npx wrangler pages secret put STRIPE_PRICE_MONTHLY
npx wrangler pages secret put STRIPE_PRICE_ANNUAL
npx wrangler pages secret put STRIPE_PRICE_TEAM
npx wrangler pages secret put RESEND_API_KEY
npx wrangler pages secret put MAIL_FROM
```

## חיבור התשלומים (Stripe)

1. פותחים חשבון Stripe ומפעילים **Billing**.
2. יוצרים שלושה Products עם מחיר מתחדש בשקלים — חודשי, שנתי, סטודיו.
   כל אחד מחזיר `price_...` שנכנס לסוד המתאים למעלה.
3. מוסיפים Webhook שמצביע ל-`https://הדומיין-שלך/api/stripe-webhook` ובוחרים את שלושת האירועים:
   `checkout.session.completed` · `customer.subscription.updated` · `customer.subscription.deleted`.
   ה-`whsec_...` שמתקבל נכנס ל-`STRIPE_WEBHOOK_SECRET`.

ה-Webhook הוא מה שמבטל גישה כשמנוי נעצר. בלעדיו מנויה שביטלה תמשיך לקרוא.

**מחשבה לפני שמתחילים:** Stripe עובד בישראל ותומך בשקלים, אבל **אינו מוציא חשבונית מס ישראלית**.
צריך לחבר מערכת חשבוניות (Green Invoice, iCount, Morning וכד׳) או לבחור סולק ישראלי.
להחלפת ספק סליקה נוגעים בשלושה קבצים בלבד: `functions/api/checkout.js`, `activate.js`, `stripe-webhook.js`.
שאר האתר לא יודע מי מחייב.

## חיבור המייל (Resend)

משמש לקישורי הכניסה. נרשמים ב-Resend, מאמתים דומיין, ומזינים את `RESEND_API_KEY` ואת `MAIL_FROM`.
ספק אחר — מחליפים רק את `functions/_lib/mail.js`.

קובץ אחד. זה כל התהליך.

מבנה הקובץ:

---

הפסקאות שלפני הסימן למטה גלויות לכולם. כאן שמים את הפתיחה
שגורמת למישהי לרצות את השאר.

נתמכים: כותרות, רשימות, טבלאות, ציטוטים, בלוקי נוסחה, מודגש ונטוי, וקיצור `{{calculator}}` שמשתיל את המחשבון בתוך הכתבה.

הבנייה מדפיסה בסוף רשימת דברים שצריך לטפל בהם לפני פרסום. כדאי לקרוא אותה.

## שינוי מחירים, שם ומיתוג

הכול ב-**`site.config.json`** — שם המגזין, שם הכותבת, הביו, המחירים, מספר הקריאות החינם והדומיין.
משנים, מריצים `npm run build`, וזה מתגלגל לכל העמודים.
`0` בשדה `freeArticlesPerMonth` מבטל את המונה ויוצר חומה קשיחה.

השאלות הנפוצות נמצאות ב-`content/faq.json`, ועמודי המידע ב-`content/pages/`.

## לפני שזה עולה לאוויר

הרשימה הזו אמיתית. שלושת הראשונים חוסמים.

- [ ] **התוכן.** שש הכתבות הן **טיוטות זרע שנכתבו כדי להראות את המבנה** — מסגרות חשיבה נכונות, אבל לא הדיווח שלך. אין בהן נתוני שוק ישראליים אמיתיים, וזה במכוון: המצאת "ממוצע שוק" הייתה הופכת את המוצר לחסר ערך. להחליף בכתיבה שלך לפני שגובים כסף.
- [ ] **עמודי תנאי השימוש והפרטיות** הם טיוטות שמרניות, לא מסמכים משפטיים. **חייבים בדיקת עורך דין** — במיוחד סעיפי הביטול, שכפופים לחוק הגנת הצרכן.
- [ ] **חשבונית מס.** לסגור את זה מול רואה החשבון לפני החיוב הראשון, לא אחריו.
- [ ] שם הכותבת, הביו וכתובת המייל ב-`site.config.json` (כרגע `רומי` ו-`hello@example.co.il`).
- [ ] המחירים — ₪45 לארבעה שבועות, ₪390 לשנה, ₪1,490 לצוות — הם **נקודת פתיחה סבירה, לא מחקר שוק**.
- [ ] הדומיין ב-`site.config.json` (משפיע על ה-canonical, ה-sitemap וה-RSS).
- [ ] `SESSION_SECRET` — מחרוזת אקראית ארוכה. החלפה שלה מנתקת את כל המנויות.
- [ ] לבדוק רכישה מקצה לקצה עם כרטיס הבדיקה של Stripe, **וגם** ביטול, ולוודא שהגישה נחסמת.

## מבנה

```
site/
├── site.config.json        מותג, כותבת, מחירים     ← נקודת העריכה הראשית
├── build.mjs               הגנרטור. ללא תלויות
├── content/
│   ├── articles/*.md       הגיליונות
│   ├── pages/*.md          על הטור, תנאים, פרטיות
│   └── faq.json            שאלות נפוצות
├── public/                 הפלט. נבנה מחדש, לא לערוך ידנית
│   └── assets/             site.css · site.js   ← אלה כן נערכים ידנית
├── functions/
│   ├── _data/bodies.js     גופי הכתבות בתשלום. נוצר אוטומטית
│   ├── _lib/               חתימות, Stripe, מייל
│   └── api/                session · article · checkout · activate · login · magic · portal · webhook
└── test/auth.test.mjs      npm test
```

`npm test` בודק את החתימות, את מונה הקריאות ואת אימות ה-Webhook — כולל ניסיונות זיוף.
כדאי להריץ אחרי כל נגיעה ב-`functions/_lib/`.
